## 文档：.sql 文件注释禁止占位符

需求：在项目文档中说明读取 .sql 文件执行时，注释里禁止使用 `%`、`{}` 等占位符。

排查方式（无 DB 连接，离线复现驱动行为）：
- 复用 `mysql-connector-python` 自身的 `RE_PY_PARAM` / `RE_PY_MAPPING_PARAM` / `_ParamSubstitutor`，
  直接在 `cursor.py` 源码上模拟 tuple 与 dict 两条参数替换路径，避免依赖真实数据库。
- 本机 mysql-connector 只在系统 Python(`AppData\Local\Python\bin\python.exe`, 9.6.0) 里装了；
  managed python 3.13 没装。PowerShell 回传 stdout 不可靠，统一 `Set-Content` 落 UTF-8 文件再 Read。

实测结论（重要，和"注释里出现 % 必崩"的直觉不同）：
- 元组/列表 params：`RE_PY_PARAM = /(%s)/` 扫整条文本 → 注释里的 `%s` 必崩
  `ProgrammingError: Not enough parameters for the SQL statement`。
- 裸 `%`（如"折扣 50%"）在 mysql-connector 的 tuple/dict 路径下**不报错**；只有 `%s` / `%(name)s` 才会。
  但手写 `sql % params`（PyMySQL 风格）时裸 `%` 会 ValueError。属高危，仍统一禁止。
- 字典 params：`%(name)s` 在注释里会被**静默替换**；键不存在则 `Failed processing format-parameters`(KeyError)。
- `DATE_FORMAT(col,'%Y-%m-%d %H:%i:%s')` 里秒的 `%s` 是典型陷阱，`%%s` 转义无效 → 改 `DATE_FORMAT(col, %s)` + 参数传入。
- `{}` 交给 lazy_mysql 直接执行**不会**报错（库内无 str.format）；风险只在下游自行 `.format()`/f-string 模板化时。
