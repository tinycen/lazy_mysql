## 1. 问题回顾

### 1.1 根因

`load_sql()` 只做「读文件 → `strip()` → 返回字符串」，不做任何注释处理与占位符校验。整条 SQL 文本（含注释、含字符串字面量）交给 mysql-connector-python 后，驱动用**纯文本正则**扫描占位符，不区分注释、字符串与代码：

| params 类型 | 驱动正则（位于 `mysql.connector.cursor`） | 行为 |
|---|---|---|
| 元组 / 列表 | `RE_PY_PARAM = b'(%s)'` | 文本中每一个 `%s` 都计数，注释与字符串内的也算 |
| 字典 | `RE_PY_MAPPING_PARAM`：`%\((?P<mapping_key>[^)]+)\)(?P<conversion_type>[diouxXeEfFgGcrs%])` | 每一个 `%(name)s` / `%(name)d` 都计数 |

扫描出 N 个占位符就要求 params 恰好提供 N 个值：

- 占位符多于参数 → `ProgrammingError: Not enough parameters for the SQL statement`
- 参数多于占位符 → `ProgrammingError: Not all parameters were used in the SQL statement`
- 字典扫到未提供的键 → `ProgrammingError: Failed processing format-parameters`（底层 `KeyError`）

### 1.2 已复核的关键事实（本次起草时实测）

1. 正则常量位于 `mysql.connector.cursor`（`RE_PY_PARAM`、`RE_PY_MAPPING_PARAM`，**bytes pattern**），`mysql.connector.abstracts` 中不存在。
2. `RE_PY_PARAM.findall(b'x %%s y %s')` 返回 **2 个**匹配 —— 即 `%%s` 中的后半段 `%s` 仍被计数，`%%` 在驱动层**不是**转义。
3. mapping 正则的 conversion_type 字符集为 `[diouxXeEfFgGcrs%]`，其中包含 `%` 本身。
4. 驱动仅在 `params` 非空时才做替换，因此「注释有 `%s` 但不传参数」长期静默，上线后某次调用补上 params 才崩。
5. `%` / `{}` 的危害分级及 A–K 实测矩阵见 [SQL_UTILS.md](../SQL_UTILS.md#1-129)，本方案不再重复，仅作为验收依据引用。

### 1.3 影响面

- 入口函数：[load_sql](../../lazy_mysql/tools/sql_utils.py)、[resolve_sql](../../lazy_mysql/tools/sql_utils.py)。
- 执行链路：[SQLExecutor.execute](../../lazy_mysql/executor.py)、[SQLExecutor.fetch_format](../../lazy_mysql/executor.py)、[SQLExecutor.query](../../lazy_mysql/executor.py)（后两者经 [result_formatter.fetch_format](../../lazy_mysql/tools/result_formatter.py) 最终仍调用 `execute()`）。
- 所有通过 `.sql` 文件路径执行的下游项目；内联 SQL 文本中写注释占位符同样会触发，但不受「文件红线」文档约束。

## 2. 修复目标与非目标

### 2.1 目标

1. **根因消除**：注释在送达驱动前被物理剥离，注释里写什么都不可能再影响占位符计数（覆盖实测用例 A、B、F、G、H、I）。
2. **可执行代码兜底**：对剥离后仍存在的危险写法（字符串内 `%s`、`%%`、数量不匹配、字典缺键）在**发往驱动之前**给出含行号、列号、修复建议的明确异常，替代驱动的晦涩报错（覆盖 C、D）。
3. **不阻断当前可正常工作的 SQL**：`DATE_FORMAT(x, '%Y-%m-%d')` 等不含秒 `%s` 的写法、裸 `%` 等仅在换驱动/手动插值时才危险的写法，降级为 **warning**，不抛异常。
4. **提供 CI 可用的 lint 工具**：把 [SQL_UTILS.md](../SQL_UTILS.md) 中「可选自检脚本」产品化，注释中 `%` / `{}` 检查成为可调用 API。
5. 注释剥离与占位符预检均为框架默认行为、始终执行、无需配置（剥离只产生空白、预检仅拦截驱动必定失败的场景，均不影响可正常执行的 SQL）。

### 2.2 非目标

1. 不替换/封装 mysql-connector 的参数化机制，不改写游标调用方式。
2. 不支持 mysql 客户端专有语法（`DELIMITER`、`source` 等 dump 脚本指令）的解析。
3. 不做 SQL 方言解析、不做标识符合法性校验。
4. 不新增使用示例、测试脚本（遵循项目约定；验收以用例矩阵列出，由维护者决定是否落成自动化测试）。

## 3. 总体设计：三层防御

```
.sql 文件 / 内联文本
        │
        ▼
┌─────────────────────────────────────────────┐
│ 第 1 层：注释剥离器 strip_sql_comments        │  ← 根因修复，默认开启
│ 引号/标识符感知的状态机；等长空格替换         │
│ 保留 /*! ... */ 可执行注释、/*+ ... */ hint  │
└─────────────────────────────────────────────┘
        ▼
┌─────────────────────────────────────────────┐
│ 第 2 层：占位符预检 validate_placeholders    │  ← 发往驱动前
│ 复用驱动自身正则计数；error 阻断 / warning   │
│ 记日志；抛 SQLPlaceholderError              │
└─────────────────────────────────────────────┘
        ▼
┌─────────────────────────────────────────────┐
│ 第 3 层：lint 工具（离线/CI 调用）            │  ← 入库前卡口
│ lint_sql_text / lint_sql_file / lint_sql_dir │
└─────────────────────────────────────────────┘
        ▼
   mycursor.execute / executemany（行为不变）
```

设计原则：

- **纯函数内核**：剥离与校验函数不依赖 executor、不打日志、不抛驱动异常，返回结构化结果，便于独立测试与复用。
- **收口在 sql_utils.py**：状态机只写一份，剥离、校验、lint 共用同一套词法状态。
- **零配置默认安全**：Executor 不加任何参数——注释剥离与占位符预检都作为框架默认行为始终执行。

## 4. 详细设计

### 4.1 第 1 层：注释剥离器

新增函数（[lazy_mysql/tools/sql_utils.py](../../lazy_mysql/tools/sql_utils.py)）：

```python
def strip_sql_comments(sql: str) -> tuple[str, list[tuple[int, int, str]]]:
    """
    剥离 SQL 注释。
    :return: (stripped_text, comment_spans)
        - stripped_text: 注释以「等长空格」替换，换行符原样保留，行列号不漂移
        - comment_spans: [(start, end, comment_text), ...]，供 lint 使用
    """
```

#### 4.1.1 词法状态机规格

单次逐字符扫描，状态集合：

| 状态 | 说明 |
|---|---|
| `CODE` | 普通 SQL 代码 |
| `SQUOTE` | 单引号字符串内 |
| `DQUOTE` | 双引号字符串内（ANSI_QUOTES 下为标识符，保守同等处理） |
| `BACKTICK` | 反引号标识符内 |
| `LINE_COMMENT` | `--` 或 `#` 行注释内 |
| `BLOCK_COMMENT` | `/* ... */` 块注释内 |

转移规则：

1. **字符串与标识符（CODE 下进入，内部不识别任何注释起点）**
   - `'`：进入 SQUOTE；内部：
     - `''` → 转义，消费 2 字符；
     - `\'` → 转义（MySQL 默认模式），消费 2 字符；
     - 再次遇到 `'` → 回 CODE。
   - `"`、`` ` `` 同理（`` `` `` 转义；双引号同样支持 `\"`）。
2. **`--` 行注释（严格按 MySQL 服务端规则）**
   - CODE 下遇到 `--` 时，**peek 第 3 个字符**：仅当它是空白/控制字符（空格、TAB、换行）或**已到 EOF**时才进入 LINE_COMMENT，剥离到行尾。
   - 第 3 个字符是普通字符（如 `a--b`）→ **不是注释，原样保留**（MySQL 中为双负号/减法）。这是正确性红线。
3. **`#` 行注释（MySQL 扩展）**
   - CODE 下遇到 `#` 即进入 LINE_COMMENT，无需后跟空格，剥离到行尾。
4. **`/* */` 块注释**
   - CODE 下遇到 `/*`：
     - `/*!` → **可执行注释，整体原样保留**（版本条件 DDL，如 `/*!50003 CREATE ... */`）；
     - `/*+` → **优化器 Hint，原样保留**（MySQL 8.0）；
     - 其余 → 进入 BLOCK_COMMENT，剥离直到遇到第一个 `*/`（MySQL 块注释不可嵌套）。
5. **替换策略**
   - 命中注释区间内，除换行符 `\n` 外的所有字符替换为空格，`\n` 保留。
   - 效果：SQL 长度不变、行号列号不漂移、后续正则计数与报错定位与原文一致；服务端收到的只是空白。
6. **幂等性**：剥离后的文本再次进入函数结果不变（`/*!`、`/*+` 保留内容再次扫描时仍被识别并保留）。

#### 4.1.2 已知限制（写入 docstring 与文档）

- `sql_mode=NO_BACKSLASH_ESCAPES` 时 `\'` 不是转义，扫描器无法在客户端感知 SQL mode；该模式下极端构造（字符串以 `\` 结尾）可能漏剥后续注释 —— 失败方向是「少剥」，不会错误篡改 SQL。
- 不处理 `DELIMITER` 重定义后的脚本体（mysqldump/存储过程 dump 文件不应走 execute 路径）。

### 4.2 第 2 层：占位符预检

#### 4.2.1 异常与问题结构

```python
class SQLPlaceholderError(ValueError):
    """占位符预检失败。issues 属性携带全部 SQLIssue，message 含聚合定位信息。"""

@dataclass(frozen=True)
class SQLIssue:
    line: int
    column: int
    end_column: int
    severity: Literal["error", "warning"]
    code: str            # 见 4.2.3
    message: str
    snippet: str         # 命中位置所在行的原文
```

#### 4.2.2 预检函数与规则

```python
def validate_placeholders(sql: str, params: Any = None) -> list[SQLIssue]:
    """对【已剥离注释】的可执行 SQL 做占位符预检；不抛异常，只返回 issues。"""
```

规则（**严格对齐 execute() 现有 params 语义**，见 [executor.py L225-L249](../../lazy_mysql/executor.py#L225-L249)）：

1. **params 为空（None / `()` / `[]` / `{}`）→ 直接返回空列表**。与驱动「params 非空才扫描」的行为保持一致，不误伤现有无参 SQL。
2. **params 归一化**（复用 execute 的判定，不改变实际传入对象）：
   - 标量 list（如 `['张三', 25]`）→ 按元组位置参数校验；
   - dict → 命名参数；
   - list 且首元素为 dict/tuple/list → 批量，SQL 只需按**单条结构**校验一次（同时沿用 execute 既有规则：空参数集、SELECT 批量由 execute 自己报错，预检不重复实现）。
3. **计数来源**：优先复用驱动正则 pattern（`mysql.connector.cursor.RE_PY_PARAM` / `RE_PY_MAPPING_PARAM`，注意 mapping 正则以 `re.VERBOSE` 编译，复用 `.pattern` 时必须重新带 `re.X`），编译为 str 版本以便报告字符级行列号；导入失败时回退到内置同语义 str 正则副本（直接复制驱动 pattern 字节串，不重写）。
4. **位置参数规则（按方向分别判定，对齐驱动真实报错路径 `cursor.py` L387-L396）**：
   - `%s` 计数（含被写进字符串的、含 `%%s` 扫出的额外匹配）**多于** len(params) → **E101 error**（驱动将在替换第 M+1 个占位符时抛 `Not enough parameters`），定位到第一个无参数可填的占位符；
   - `%s` 计数**少于** len(params) → **E102 error**（驱动替换完后 `psub.remaining != 0`，抛 `Not all parameters were used`）。
5. **字符串字面量内的占位符（覆盖用例 C/D/E）→ W105 warning，不阻断**：
   - 驱动不看引号，字符串内的 `%s` 同样参与计数与替换——用例 E（`DATE_FORMAT(created_at, %s)` 格式串走参数）正是利用这一点，是合法写法；
   - 因此字符串内出现占位符只发 **W105 warning** 提示「若为 DATE_FORMAT 时间格式串请整体参数化」；若它同时导致计数不匹配，由 E101/E102 统一报 error。
6. **命名参数规则（对齐 `_bytestr_format_dict` 真实行为，已实测）**：
   - 扫描到的每个 mapping key 不在 params 中 → **E103 error**（驱动底层 `value_dict[key]` 抛 `KeyError`，包成 `Failed processing pyformat-parameters`）；
   - conversion_type 非 `s` 且非 `%`（如 `%(name)d`）→ **E104 error**（驱动 `replace()` 对此抛 `ValueError: Unsupported conversion_type`）；
   - `%(...)% `（conversion_type 为 `%`）是字面量百分号，跳过；
   - **params 中多余的键不检查**——已实测驱动 `_bytestr_format_dict` 对多余键静默忽略（合法用法），原 W102 废止。
7. **其余 `%` 分类扫描（W103 warning，不阻断）**：遍历全部 `%`，扣除已识别占位符匹配后：
   - `%%`（含 `%%s` 中的首个 `%`）→ W103，消息注明「`%%` 不是驱动层转义」；
   - 裸 `%` / `%Y` / `50%` 等 → W103（当前驱动安全，换驱动/手动插值时危险）；
   - 行/块注释区间内的 `%` 不参与 W103 扫描（内联 SQL 场景降噪；注释 `%s` 若造成计数不匹配已由 E101/E102 覆盖）。
8. `%` / `{}` 检查**不针对可执行代码中的花括号**（MySQL 不解析、lazy_mysql 也不解析），花括号只在第 3 层 lint 的注释维度检查。

#### 4.2.3 Issue 代码表

| code | severity | 含义 |
|---|---|---|
| E101 | error | `%s` 占位符数量多于参数个数（驱动将报 `Not enough parameters for the SQL statement`） |
| E102 | error | `%s` 占位符数量少于参数个数（驱动将报 `Not all parameters were used in the SQL statement`） |
| E103 | error | 命名占位符键在 params 中缺失（驱动底层 `KeyError`） |
| E104 | error | 命名占位符使用驱动不支持的转换类型（驱动仅支持 `s`；`%(...)% ` 为字面量 `%`） |
| W101 | warning | 注释中出现 `%`（仅 lint 产出；运行时注释已剥离） |
| W103 | warning | 非占位符 `%`：裸 `%`、`%Y`、孤立 `%%` 等 |
| W104 | warning | 注释中出现 `{` / `}`（仅 lint 产出） |
| W105 | warning | 字符串字面量内出现占位符（如 DATE_FORMAT 时间格式串），建议参数化 |

> 已废止：原 W102（字典多余键）——实测驱动静默接受多余键，不检查；原 E104（`%%` 计数）——`%%s` 造成的计数差由 E101/E102 承接，孤立 `%%` 由 W103 承接。

### 4.3 第 3 层：lint 工具（入库前 / CI）

```python
def lint_sql_text(sql: str) -> list[SQLIssue]:
    """复用 strip_sql_comments 返回的 comment_spans：
       - 注释内出现 % → W101；出现 { 或 } → W104（与 SQL_UTILS.md 红线一致）；
       - 再对剥离后的可执行文本调用 validate_placeholders 的无参扫描口径
        （仅产出 E103/W103 等不依赖 params 的结构性问题）。"""

def lint_sql_file(sql_path) -> list[SQLIssue]: ...
def lint_sql_dir(dir_path, pattern: str = "**/*.sql") -> list[tuple[Path, list[SQLIssue]]]: ...
```

- lint 不读 params，无法做 E101/E102 数量校验 —— 这是运行时预检的职责，不越界。
- 行为对齐 [SQL_UTILS.md](../SQL_UTILS.md) 第 101–127 行的自检脚本，但补全块注释、引号感知、行列号与代码分类。
- CLI 入口（`python -m lazy_mysql.tools.sql_utils <path>`）**本期不做**，列为可选。

### 4.4 集成点与 API 变更

#### 4.4.1 `load_sql` / `resolve_sql`

```python
def load_sql(sql_path, strip_comments: bool = True) -> str: ...
def resolve_sql(sql, strip_comments: bool = True) -> str: ...
```

- `strip_comments` **仅对文件路径加载生效**；内联字符串仍原样返回（保留现有「智能判断 + 幂等」契约，不做静默改写）。
- `resolve_sql` 对已是 SQL 文本的输入，新参数无效果（docstring 写明）。

#### 4.4.2 `SQLExecutor`（[executor.py](../../lazy_mysql/executor.py)）

`__init__` **签名不变**（零配置），注释剥离与预检都作为框架默认行为始终执行：

`execute()` 改动（[L217-L224](../../lazy_mysql/executor.py#L217-L224) 附近）：

```python
sql = resolve_sql(sql)   # 文件路径加载时 resolve_sql/load_sql 内部已默认剥离注释
issues = validate_placeholders(sql, params)
for w in issues:
    if w.severity == "warning":
        self.logger.warning("[%s] %s:%s %s", w.code, w.line, w.column, w.message)
errors = [i for i in issues if i.severity == "error"]
if errors:
    self.close()
    raise SQLPlaceholderError(errors)   # 不进入驱动、不触发重连
```

- 预检在连接态检查之前即可执行（纯计算）；error 时 `close()` 后直接抛出，**不经过 `_handle_connection_error`**，避免被误判为连接错误去重连。
- warning 只经 logger 输出，不改变执行流程。
- `fetch_format()` 中对 `resolve_sql` 的调用同样自动获得注释剥离；实际预检在其下游 `execute()` 内完成，不重复执行。
- 重连重试路径自然复用预检（每次 execute 调用都跑），无额外改动。

#### 4.4.3 导出变更

- [lazy_mysql/tools/__init__.py](../../lazy_mysql/tools/__init__.py)：增补导出 `strip_sql_comments`、`validate_placeholders`、`lint_sql_text`、`lint_sql_file`、`lint_sql_dir`、`SQLPlaceholderError`、`SQLIssue`。
- [lazy_mysql/__init__.py](../../lazy_mysql/__init__.py)：仅增补 `SQLPlaceholderError`（lint 工具走 `lazy_mysql.tools` 命名空间，避免顶层膨胀）；同步更新 `__all__`。
- [tests/test_import.py](../../tests/test_import.py) 的导出名单按实际变更同步。

## 7. 验收标准

### 7.1 功能验收：实测用例 A–K 映射

驱动版本固定 mysql-connector-python 9.6.0。SQL 经文件路径传入时注释默认被剥离、预检始终执行。

| 用例（来自 SQL_UTILS.md） | 修复前 | 修复后预期 |
|---|---|---|
| A 注释 `%s` + 正文 `%s`，1 参数 | ❌ Not enough parameters | ✅ 注释被剥离，正常执行 |
| B 注释 `LIKE '%s%'` | ❌ Not enough parameters | ✅ 正常执行 |
| C `DATE_FORMAT(…,'…%s')` + 1 参数 | ❌ Not enough parameters | ❌ 抛 **E103**（行号 + 参数化建议），不再产生驱动晦涩报错 |
| D `%%s` 转义尝试 | ❌ 仍报错 | ❌ 抛 **E101/E104**（计数 2≠1，提示 `%%` 无效） |
| E 格式串走参数 `%s` | ✅ | ✅ 无 issue |
| F 注释裸 `%`（50% 以上） | ⚠️ 高危通过 | ✅ 注释被剥离；未剥离场景（inline）无 error |
| G 注释 `%(not_exist)s` | ❌ KeyError | ✅ 注释被剥离，正常执行 |
| H 注释 `%(uid)s` 静默替换 | ⚠️ 不报错但语义被篡改 | ✅ 注释被剥离，不再被替换 |
| I 注释 `{table}` 直接执行 | ✅ 不报错 | ✅ 注释被剥离；lint 对该文件报 **W104** |
| J 含 `-- 模板 {}` 后自行 `.format()` | ❌ IndexError | lint 报 W104，入库前卡口 |
| K 含 `-- 折扣 50%` 后自行 `sql % params` | ❌ ValueError | lint 报 W101，入库前卡口 |

### 7.2 回归与边界

1. 无 params 的现有 SQL（含 `DATE_FORMAT(x,'%Y-%m-%d')`）：无 error、无阻断。
2. `/*!50003 ... */`、`/*+ INDEX(t idx) */`：执行文本中**原样保留**。
3. `SELECT 'a--b'`, `SELECT '100%'`, `` SELECT `a--b` ``：引号/反引号内内容零修改。
4. `a--b`（无空格）：不视为注释，原文保留。
5. 剥离后文本长度与原文一致、换行位置一致（可用 A–K 夹具断言）。
6. 如需保留注释（如调试场景比对 SQL 原文），可直接调用 `load_sql(path, strip_comments=False)` / `resolve_sql(path, strip_comments=False)`；执行链路中的预检始终生效，但其 error 项仅覆盖驱动必定报错/静默错配的场景，不影响可正常执行的 SQL。
7. dict params 缺键（inline SQL，默认配置）：抛 **E103** 且不触发连接重连。
8. 批量参数 list[dict] / list[tuple]：按单条结构校验，不影响 executemany 原有分支。

## 8. 兼容性、风险与回滚

| 风险 | 等级 | 应对 |
|---|---|---|
| 状态机误判导致 SQL 被错误改写 | 中（最高风险项） | 等长替换只产生空白，不可能生成新 token；`/*!` `/*+` 保留；第 7 章边界用例全覆盖；失败方向设计为「少剥」而非「错改」 |
| 默认行为变化（发往服务端的文本不含注释） | 低 | 注释对 SQL 语义无影响；受影响面仅日志/审计中 `cursor.statement` 的文本差异 |
| 预检误阻断现有可工作 SQL | 低 | error 仅覆盖驱动必定拒绝的场景；裸 `%`/`%Y`/多余键一律 warning；params 为空完全跳过 |
| 未来驱动版本移动/删除正则常量 | 低 | ImportError 回退内置正则，功能不中断 |
| NO_BACKSLASH_ESCAPES 等特殊 SQL mode | 低 | docstring 与 [SQL_UTILS.md](../SQL_UTILS.md) / [SQL_MODE.md](../SQL_MODE.md) 明示限制 |

**回滚方式**：注释剥离与预检均为框架默认行为、始终执行，无需也无法在 Executor 上关闭；如需保留注释文本可调用 `load_sql(path, strip_comments=False)`。剥离只产生空白、预检 error 仅覆盖驱动必定报错的场景，均不改变可正常执行 SQL 的行为。lint 为纯离线工具，不影响运行链路。

**已实测确认的关键行为**（评审后核对完毕）：

1. dict params 含未使用键时，驱动 `_bytestr_format_dict` 对多余键**静默忽略**（合法用法）——因此不做检查，原 W102 废止。
2. dict params 缺键时驱动抛 `KeyError`（包成 `Failed processing pyformat-parameters`）——对应 E103。
3. 驱动 mapping 正则的 conversion_type 中仅 `s` 与 `%` 有效，其余（如 `%(name)d`）在 `replace()` 中抛 `ValueError` —— 对应 E104。
